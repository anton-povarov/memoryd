# Use Go, SQLite, and a filesystem CAS for the server

The main memoryd server is a Go application using local filesystem content-addressed storage for immutable Blob bytes and SQLite as the authoritative store for Memories, metadata, Facts, Understanding Runs, active-Run selection, logs, and Understanding State. FTS5 is a rebuildable projection inside SQLite. Long-running understanding work uses `destel/rill` for bounded concurrency inside the server. A single-file import request stays open through understanding and returns streamed progress plus a terminal result. Once its Blob and `InProgress` Memory row commit, understanding is detached from client cancellation; startup recovery reprocesses interrupted `InProgress` Memories. There is no persistent queue table, separate worker service, or external queue. A checked-in OpenAPI specification is the HTTP contract and generates Go handler interfaces and request/response types.
