# Clients own directory import workflows

In the client/server architecture, a client enumerates directories, excludes ignored entries such as `.git` and `.DS_Store`, uploads regular files individually, and handles retry, skip, or abort interaction. The initial browser client uses a directory picker, deterministically orders the resulting flat file list, and uploads sequentially without a server-side batch abstraction; relative paths are retained while absolute paths may be unavailable. Abort stops later uploads but does not cancel understanding already started for the current durable Memory. A Duplicate response includes the existing Memory identity and Understanding State for recovery without enrichment. The server owns single-file validation, deduplication, storage, and understanding, avoiding filesystem assumptions that only make sense on the importing device.
